# Synora Wiki 设计规范

文档版本：1.0
状态：CONFIRMED（设计约束）；原生视觉验收 NOT_RUN
适用范围：macOS 主应用、原型、后续 SwiftUI 实现
视觉参考：本地 `local-reference/high-fidelity/` 下概念图与 React 原型；不随 Git 分发。当前 PNG 实测 1513×863，不能视为 1280×720 验收基线。无本地参考时不得臆造一比一对照。

## 1. 设计目标

Synora Wiki 不是“另一个配置型知识库”，而是一个可以长期居住的个人记录空间：有 Apple 手记般的温度、图片叙事和克制细节，也有真正可检索、可演进、由模型低干扰维护的知识结构。

设计必须同时成立的四个条件：

1. **记录优先**：打开后立即进入内容，不用先决定数据库、目录或模板。
2. **结构隐身**：主题、标签、关联、索引和知识页存在，但不抢占正文注意力。
3. **AI 可见但不喧宾夺主**：AI 以侧边助手、行内建议和后台整理三种层级出现。
4. **精致而平静**：浅色、扁平、低饱和、小圆角；拒绝高透磨砂、彩色仪表盘和大卡片拼装。

## 2. 产品形态

### 2.1 单一主窗口

正式应用只有一个主要工作窗口。除系统文件选择器、权限确认、设置和必须的模态任务外，不通过新窗口或连续弹窗完成日常工作。主窗口由四列构成：

| 区域 | 原生目标内容宽度（pt） | 职责 |
|---|---:|---|
| 全局侧边栏 | 180 pt | 首页、收件箱、知识库、手帐分类、工具 |
| 记录列表 | 308 pt | 搜索、笔记/手帐切换、按时间分组的记录 |
| 正文编辑器 | 弹性，最小 500 pt | 写作、媒体编排、行内 AI、保存状态 |
| 上下文检查器 | 280 pt | 地点、天气、照片、关联内容、AI 助手/Skills |

原生几何使用逻辑点（pt），截图使用像素（px），测量时记录实际 backing scale，不假定二者相等；布局/绘制优先使用 AppKit backing 坐标转换方法而非手工乘缩放系数。表中列宽包含列内边框；四栏最小合计 1268 pt。1280 pt 内容区的编辑器为 512 pt，1440 pt 为 672 pt。应按实际可用内容区计算，系统 chrome、分隔器或辅助字号占用额外空间时计入预算。

顶部应用工具区以 52 pt、正文状态栏以 32 pt 为初始目标；原生标题栏与窗口控制遵循系统布局和 safe area，不强行复刻 Web traffic lights。最小窗口内容区目标为 1100×720 pt，推荐 1440×900 pt；截图矩阵保留 1280×720、1440×900、1728×1117 pt，并记录实际窗口内容区及输出 px。

当内容区不足以容纳四栏最小宽度（至少 1268 pt，额外系统占用另计）时自动折叠检查器，并保留工具栏恢复入口；不得挤压编辑器或裁切。恢复检查器前必须重新计算预算，必要时先折叠导航。原 Web 的 930/760 px 断点不作为原生合同。P1 在实际 SwiftUI/AppKit 窗口中校准最小尺寸、列宽、系统工具栏与辅助字号；任何调整更新本文件并保存测量依据，不减少功能或牺牲正文可达性。

### 2.2 信息架构

```text
Synora Wiki
├── 首页 / 今日 / 收件箱
├── 知识库
│   ├── 所有笔记
│   ├── 主题
│   ├── 标签
│   ├── 收藏
│   └── 回收站
├── 手帐本
│   ├── 全部手帐
│   ├── 年份
│   └── 旅行 / 生活 / 日常 / 灵感
└── 工具
    ├── AI 对话
    ├── AI Skills
    └── 设置
```

“笔记”和“手帐”共享编辑器与底层知识库。二者差别只体现在默认模板、列表叙事和上下文面板：笔记更强调主题与来源，手帐更强调时间、地点、天气、照片、音乐和身体状态。

## 3. 布局与栅格

- 基础间距单位：4 px。
- 常用间距：4 / 8 / 12 / 16 / 20 / 24 / 28 / 32 px。
- 侧边栏水平内边距：9–10 px；列表水平内边距：14 px；正文画布水平内边距：28 px。
- 正文最大内容宽度：820 px；在可用区域内水平居中。
- 主分隔线：1 px；只使用结构分隔，不用卡片阴影代替层级。
- 图文拼贴比例：主图约 61%，副图约 39%；行列间距 4 px；高度在 220–310 px 之间随窗口变化。
- 检查器卡片间距：10 px；内部边距 10–12 px；卡片只能承载单一语义组。

## 4. 色彩

以下源自 Web 原型的 px 尺寸在原生实现中视为初始 pt 目标，光栅截图除外；边框须按 scale 对齐物理像素。所有颜色以 sRGB 为准。正式实现应生成语义颜色资源，不在视图内散落十六进制值。

| Token | 值 | 用途 |
|---|---|---|
| `ink.primary` | `#151A2D` | 标题、主要文本 |
| `ink.secondary` | `#687083` | 正文辅助、元数据 |
| `ink.tertiary` | `#969CAB` | 仅装饰；承载信息的元数据/占位使用 `ink.secondary` |
| `surface.canvas` | `#FFFFFF` | 编辑器与卡片 |
| `surface.sidebar` | `#F4F5F7` | 全局侧边栏 |
| `surface.list` | `#FBFBFC` | 记录列表 |
| `surface.inspector` | `#F7F8FA` | 检查器底色 |
| `border.subtle` | `#E8EAF0` | 分隔线与轻边框 |
| `accent.primary` | `#5C75E7` | 选择与焦点；小字号链接改用 `accent.text` |
| `accent.text` | `#5268C8` | 小字号链接文字，仍需逐背景验证对比度 |
| `accent.soft` | `#EAF0FF` | 选择背景 |
| `ai.primary` | `#7669EF` | AI 身份标记 |
| `journal.highlight` | `#EF7FB4` | 手帐小型情绪强调 |
| `warning.inline` | `#F3A51D` | 行内优化入口 |

上述配色是起点，实际文字/背景组合必须通过第 11 节对比度要求；增加对比度模式优先系统可访问语义色。`#969CAB` 对白色仅约 2.75:1，不能作为有信息的弱文字。

不得使用渐变作为布局背景。AI 紫色、手帐粉色和黄色只允许作为小面积功能标识，不得扩展成大片色块。

## 5. 字体与排版

字体顺序：`SF Pro Display` / `SF Pro Text` / `PingFang SC` / 系统无衬线。中文正文使用系统苹方，不捆绑第三方字体。

| 样式 | 字号 / 行高 | 字重 | 用途 |
|---|---|---:|---|
| 文档标题 | 25–33 / 1.2 | 720 | 当前记录标题 |
| 节标题 | 16 / 1.3 | 650 | 今日收获、留给明天 |
| 正文 | 12.5 / 1.78 | 400 | 连续阅读文本 |
| 引用 | 13 / 1.55 | 400 | 强调语句 |
| 列表标题 | 12.5 / 1.25 | 600 | 记录名称 |
| 导航 | 12.5 / 1.3 | 400–530 | 侧栏项 |
| 元数据 | 10–10.5 / 1.35 | 400 | 日期、地点、标签 |
| 分区标签 | 11 / 1.3 | 500 | “知识库”“工具” |

正文不使用纯黑；按可用画布自然换行，宽画布可参考 65–78 个中文字符，不能在窄编辑器强制该行宽。标题与正文之间不放多余卡片或营销式提示。

## 6. 圆角、边框与阴影

- 控件圆角：6–8 px。
- 列表选择和图片圆角：8–9 px。
- 检查器卡片：10 px。
- 浮动格式工具栏：11 px。
- 大容器不使用圆角；列本身必须贴合窗口边缘。
- 常规卡片阴影：`0 1px 2px rgba(22,28,45,.04), 0 5px 16px rgba(22,28,45,.035)`。
- 只有浮动工具栏可使用更明显的阴影；不使用高透玻璃或强模糊层。状态栏的轻度材质效果仅用于保持文字可读性，正式 SwiftUI 实现可用接近不透明的系统材料并验证色差。

## 7. 图标与媒体

- 原型使用 Phosphor Icons 的 regular 线性图标；正式 macOS 实现使用语义最接近的 SF Symbols。
- 默认图标尺寸 16 px，工具栏 15–17 px，状态图标 12–14 px。所有图标必须有可访问名称和提示。
- 不使用 emoji 充当功能图标。
- 照片必须真实、自然、低饱和，优先使用用户媒体；空状态使用系统图标与文字，不使用装饰性插画堆叠。
- 媒体块支持照片、视频、音频、PDF/文档和链接预览；缩略图只裁剪显示，不改写原文件。

## 8. 核心组件规范

### 8.1 全局侧边栏

- 行高 33 px，左右 10 px，图标与文字间距 10 px。
- 默认透明，悬停 `#E8EBF2` 的 82% 视觉强度；选中背景 `#E2E7F4`、前景 `#526FE1`。
- 仅显示单一选中项。收件箱数字靠右，不用彩色 badge。
- 支持 ⌘⇧S 收起/展开，动画 180 ms ease。

### 8.2 记录列表

- 搜索框 34 px 高，列表项最小 79 px，缩略图 51 × 51 px。
- 默认按修改时间或手帐日期分组；组标题和列表一起滚动。
- 选中项使用浅蓝整行背景，不增加外描边。
- “笔记/手帐”分段选择器高度 34 px。切换必须保留搜索词并恢复各自上次选中项。
- 新建记录应直接出现在列表并获得焦点，不弹模板选择框；模板可在斜杠菜单中切换。

### 8.3 编辑器

- 标题、正文与列表直接就地编辑，不出现“进入编辑模式”。
- 支持段落、H1/H2/H3、列表、任务、引用、代码、分隔线、表格、折叠块、媒体、链接预览和 callout；功能少于 Notion，但核心排版完整。
- `/` 打开斜杠菜单；`@` 引用笔记/主题；`[[` 快速链接；拖拽、粘贴和文件选择均可插入媒体。
- 选择文本后，格式工具栏在选区附近出现；未选择时不持续悬浮。当前原型为可发现性在聚焦时展示，正式版以选区为准。
- 自动保存有“保存中/已保存/冲突待处理/离线”四种状态；正文输入不得被保存动画打断。
- 撤销/重做必须包含 AI 接受、块移动、媒体替换与元数据修改。

### 8.4 上下文检查器

- 默认展示与当前记录直接相关的地点、天气、相关照片和 AI 助手。
- 无对应数据时整个模块消失，不保留空卡片。
- 检查器可在“上下文”和“AI Skills”之间切换；切换不改变正文选区与滚动位置。
- 所有 AI 建议先显示结果或变更摘要；结构性写入必须允许比较、接受、拒绝与撤销。

### 8.5 行内 AI 建议

- 建议以当前光标后的低对比度 ghost text 或可审阅 diff 出现，不把原文替换掉。
- `Tab` 接受当前建议，`Esc` 拒绝，`⌘↩` 展开完整建议；按字符继续输入时建议自动重算或消失。
- 等待超过 450 ms 才出现轻量加载状态，避免闪烁。
- 建议只读取当前块、相邻块和用户明确授权的上下文。远程模型发送范围必须可见。

### 8.6 AI Skills

- Skills 列表展示图标、名称、单句能力、启用状态和权限摘要。
- 安装前展示来源、版本、签名、所需权限、可调用工具、数据外发范围和卸载方式。
- 默认只读；写入、网络、文件夹、照片、日历等权限分别授权。开关不等于授权升级。

## 9. 手帐体验

手帐不是独立应用壳，而是同一知识系统中的“叙事视图”。默认元数据可包含日期、地点、天气、照片、音乐、运动摘要和情绪；元数据在正文上方用单行弱化呈现，缺失项不占位。

手帐模板允许精致编排，但必须遵守：

- 用户可以从空白记录开始；模板不是必选步骤。
- 图片自由组合仍映射到稳定媒体块，避免 Apple 手记长文和插图混排时的结构错乱。
- 自动拉取的数据都标记来源，并允许逐项关闭。
- 健康数据只显示用户主动选取或明确授权的摘要，不展示模型推断的医疗结论。

## 10. 动效与反馈

- 悬停/按下：120 ms ease；栏位折叠：180 ms ease；检查器切换：160–220 ms ease-out。
- 列表切换只做 4–8 px 位移和透明度过渡，不做缩放卡片或大范围弹簧动画。
- AI 流式输出以文本增量呈现，不用持续旋转的炫光。
- 遵循“减少动态效果”；开启后所有非必要动效压缩至近零。
- 成功保存不弹 toast；失败、冲突、权限和需要用户决策时才出现持久反馈。

## 11. 键盘、辅助功能与本地化

- 完整支持键盘导航、VoiceOver、Full Keyboard Access、系统焦点环和菜单命令。
- 所有点击目标不小于 28 × 28 pt；高频主操作尽量达到 32 pt。
- 常规文本对比度达到 WCAG 2.2 AA；元数据也不得低于 4.5:1，装饰元素除外。
- 动态字号不应破坏四列结构；正文至少可放大至 160%。
- 文案先支持简体中文与英文；布局不得假设固定中文长度。

## 12. 明确禁止

- 不使用高透磨砂玻璃、霓虹渐变、发光边框或多色状态大卡片。
- 不把首页做成项目管理仪表盘，不显示商业指标、团队成员或协作流水。
- 不以大量模态窗口、抽屉嵌套或页面跳转完成记录。
- 不让用户手工维护 AI 生成的目录、反向链接或索引文件。
- 不在本阶段设计知识图谱视图；禁止用简单气泡网络作为临时成品。未来图谱必须先通过独立高保真设计，达到节点清晰、缩放稳定、可筛选且有优雅力导向动画的标准。

## 13. 视觉验收

每个正式界面按第 2.1 节三个内容区尺寸进行原生截图回归，测量协议见 [TESTING.md](TESTING.md)：

1. 以 P1 校准并审批的原生同尺寸基线进行回归，关键壳层结构 SSIM 目标不低于 0.95；首次建立基线须同时对照本地设计参考，不可用当前输出自证一致。
2. 列宽、栏高、基线和内边距误差不超过 2 pt；字体大小误差不超过 1 pt。
3. 核心语义色 ΔE 2000 不超过 2；图片内容不计入像素差。
4. 不允许遮挡、截断、不可见滚动条、跳动布局、非预期横向滚动或焦点丢失。
5. 交互状态必须覆盖默认、悬停、按下、聚焦、选中、加载、空、失败、离线和冲突。
6. 通过键盘完整完成“新建—编辑—插图—调用 AI—接受建议—查找—恢复版本”流程。

对照结果记录在 [design-qa.md](design-qa.md)。平台语义与可访问性校准须说明原要求、实测问题、调整和复验；不得因旧截图不准确而降低质量门槛。

## 14. 平台依据

- [Apple Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/)：保证文字与背景可辨识；具体配色仍需实测。
- [NSWindow.backingScaleFactor](https://developer.apple.com/documentation/appkit/nswindow/backingscalefactor)：记录显示缩放；Apple 建议布局/绘制使用 backing 坐标转换方法，不直接依赖缩放系数。

列宽、折叠阈值、SSIM 与误差预算是本项目约束，不是 Apple 官方数值。
