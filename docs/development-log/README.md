# 开发日志规范

每个 Phase 只保留一份开发日志，不为普通增量新建日志文件。文件名固定为：

```text
YYYYMMDD-Phase-X-开发日志.md
```

每次准备提交 Git commit 前，在当前 Phase 文件最上方追加一轮，最新在上。内部标题固定为：

```text
YYYY-MM-DD HH:mm · P X · 第 N 步，对应开发计划中的 M 步 · 本轮任务
```

每次日志更新使用以下结构：

1. 本轮任务列表（对应开发计划中的哪一步，都有哪些执行步骤，以列表的形式整理）
2. 本轮任务完成度
3. 测试方式
4. 测试结果
5. 用户如何进行手工测试
6. 风险预估与规避
7. 下轮建议
8. 本轮任务大白话讲解

记录原则：

- 写真实完成内容、实际命令和退出结果；未运行就明确写未运行。
- 大白话部分先讲业务目的、用户看到什么和数据流，再讲专业术语。
- 历史错误和修正都保留结论，不能把失败改写成一次成功。
- Commit SHA 可在提交后下一轮补记；Git 历史是原始旧日志的长期追溯入口。
- “测试方式/结果”列出实际测试命令和运行次数；同一命令因修正重跑时记录总次数，不复制完整终端输出。
- 连续 30 分钟没有业务代码、可运行测试、已确认决定或明确阻塞证据时，在“风险预估与规避”记录停止原因和缩小范围结果。
