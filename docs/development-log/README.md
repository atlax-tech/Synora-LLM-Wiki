# 开发日志规范

每个阶段使用一份日志。只在有意义的开发批次、决策、阻塞或阶段状态变化时追加；普通 commit 不强制写日志。

文件名使用 `YYYYMMDD-Phase-X-开发日志.md`，新记录放在最上方。每轮最多记录：

1. 范围与结果。
2. 实际运行的验证及结果。
3. 未验证项、阻塞或风险。
4. 确有必要时记下下一步。

不复制完整 diff、终端输出或 Agent 对话，不统计 Token、代码行数、子 Agent 数和无法准确计量的耗时。失败和未运行项不得改写为成功。

阶段日志不要求 Rubric、全量风险登记或独立对抗审查。这些只在完整版本/发布候选收口或用户明确要求时记录。
