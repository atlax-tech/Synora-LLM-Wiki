# Synora Wiki 产品需求文档

文档版本：1.1
状态：CONFIRMED（需求已确认，不代表已实现）
面向版本：完整个人版
平台优先级：macOS 优先，iPhone 伴侣能力按集成阶段提供
产品性质：个人使用、开源、非商业化

## 1. 文档目的

本文把概念讨论与高保真设计收敛为可设计、可开发、可测试的产品要求。阶段拆分只决定实现顺序，不代表缩减最终功能；标记为“后续阶段”的能力仍属于承诺范围。

## 2. 背景与问题

现有记录工具通常在两端之间摇摆：

- Obsidian 等知识库工具能力强，但学习、插件、同步和结构维护成本高，容易让维护超过记录本身。
- Notion 的 block 编辑体验优秀，但功能与配置过多，容易转向项目管理而非安静写作。
- Apple 手记在隐私、生态联动、情绪和视觉体验上优秀，但长文与多媒体编排不稳定，缺少 AI 与知识组织能力。
- Apple 备忘录足够轻，但内容结构、关联、排版和知识库能力不足。

核心机会不是继续叠加功能，而是让系统承担结构维护，让用户只需记录、审阅和偶尔校正规则。

## 3. 产品愿景

Synora Wiki 是用户唯一需要维护的个人记录空间：日记、随笔、资料、阅读笔记、灵感和长期知识都进入同一底层；它既像一本精致的手帐，也像一个会自我整理、可追溯、可纠错的私人知识库。AI 随记录、整理、查询与回顾自然触发，聊天只是入口之一。

## 4. 产品原则

1. **记录成本最低**：任何内容都能在 10 秒内开始记录。
2. **维护由系统承担**：目录、索引和结构检查自动维护；摘要、标签、关联和语义判断由模型在后台建议或完成。
3. **人的原文不可被悄悄改写**：用户内容、原始来源和模型派生内容严格分层。
4. **任何 AI 写操作可追溯、可比较、可撤销**。
5. **本地优先与 BYOK**：无网络也能记录、搜索和阅读；模型供应商可替换。
6. **原生 Mac 体验**：键盘、菜单、拖放、撤销、窗口、系统服务和 Apple 生态按平台习惯工作。
7. **功能完整但界面克制**：能力可以丰富，首屏和日常路径不能复杂。

## 5. 目标与非目标

### 5.1 目标

- 用一款应用覆盖日常手帐与长期知识管理，不再分散到多款产品。
- 提供稳定、舒适、接近 Notion 易用性的结构化多媒体编辑器。
- 实现 LLM Wiki：原始资料层、模型维护知识层与可演进规则层。
- 内置轻量模型任务、深度 Agent sidecar、行内 AI 建议和可安装 Skills。
- 支持本地模型与主流云模型 BYOK，用户掌握成本与数据外发范围。
- 通过 iCloud 和 Apple 平台能力联动照片、音乐、地点、天气与用户授权的健康摘要。
- 保持内容可导出、可迁移、可从开放格式重建。

### 5.2 非目标

- 不做商业化、付费墙、增长、团队管理、工作流审批或企业权限体系。
- 不复刻 Notion 的数据库、项目管理与站点发布能力。
- 不把插件数量当产品目标；Skills 必须围绕记录与知识工作。
- 当前阶段不产出知识图谱 UI。底层关系会实现，图谱可视化另立设计门槛。
- 不承诺第三方在线服务永久可用；所有集成都必须有离线和撤销路径。

## 6. 目标用户与使用环境

### 6.1 核心用户

唯一核心用户是应用所有者本人：有大量碎片记录、日记、图片、阅读资料与思考，希望获得长期价值，但不愿投入大量时间设计和维护知识库。

### 6.2 环境

- 主要设备：Apple Silicon Mac。
- 高频场景：桌面长文写作、资料整理、当天复盘、图片日记、查找旧知识。
- 辅助设备：iPhone 用于采集照片、位置、音乐和用户选择的健康摘要；不要求移动端复刻完整编辑器。
- 网络：允许长期离线；AI 云能力和同步在恢复网络后续跑。

## 7. 成功标准

这是个人产品，不使用 DAU、转化率或收入指标。以可感知价值与可靠性衡量：

| 指标 | 目标 |
|---|---:|
| 从启动到可输入 | 冷启动后 ≤ 1.5 秒 |
| 从意图到新建记录可输入 | ≤ 10 秒，且不经过模态选择 |
| 用户每周手工维护结构的时间 | 低于记录时间的 10% |
| 已授权资料的后台处理完成率 | ≥ 99.5%，失败可重试 |
| AI 结构写入的可追溯率 | 100% |
| AI 结构写入的可撤销率 | 100% |
| 同步冲突静默覆盖 | 0 次 |
| 10,000 条记录全文检索 P95 | ≤ 150 ms |
| 日常编辑崩溃导致的已确认内容丢失 | 0 |

## 8. 术语

- **记录（Record）**：笔记与手帐的统一实体。
- **块（Block）**：记录正文中的稳定结构单元。
- **原始来源（Raw Source）**：导入的网页、文件、剪藏、对话等不可变内容及其元数据。
- **知识页（Wiki Page）**：模型从原始来源和用户记录中维护的派生页面。
- **规则（Schema/Rules）**：描述知识库目的、结构、字段、写作和链接规则的可版本化文件。
- **建议（Proposal）**：AI 尚未应用的修改计划或 diff。
- **作业（Job）**：可恢复、幂等的后台 AI/索引/同步任务。
- **Skill**：带清单、说明、权限和工具声明的可安装 AI 能力包。

## 9. 关键用户旅程

### 9.1 快速记录

1. 用户启动应用或使用全局快捷键。
2. 无论当前视图是什么，新建都直接打开空白记录并获得标题/正文焦点；位置、类型、模板与标签均非前置选择。
3. 用户输入文字、粘贴图片或拖入文件。
4. 内容立即本地保存并可通过原文检索；后台整理完成后补充元数据、主题和候选关联，不移动用户的编辑位置。
5. 用户继续写作，不被分类流程打断。

### 9.2 精致手帐

1. 用户切换“手帐”，创建当天记录。
2. 系统在授权范围内带入日期、地点、天气、照片候选与音乐记录。
3. 用户选图并用稳定媒体块编排；长文与媒体互不破坏布局。
4. AI 可生成旅行摘要、今日收获、待办或回顾建议。
5. 记录自动进入相关主题和时间线，同时保留手帐视图的精致呈现。

### 9.3 资料入库与知识维护

1. 用户拖入文件、粘贴链接或发送文本到收件箱。
2. 系统先保存原始内容和来源，再创建 ingest 作业。
3. 轻量模型提取候选概念、事实、标签、链接与知识页更新方案。
4. 低风险派生写入按规则自动应用；高风险合并、删除或事实替换进入审阅。
5. 用户从变更摘要查看“为何修改、引用何处、使用何模型”，可撤销。

### 9.4 查找与问答

1. 用户用全文、语义、时间、地点、标签或来源搜索。
2. 系统返回记录、原始来源、知识页和媒体，并标明命中原因。
3. AI 问答按问题读取知识页与原文证据，覆盖尚未整理的新记录且仅使用授权内容；证据不足时扩大检索或明确未知，答案逐条引用本地来源。
4. 用户可把答案保存为新记录或知识页建议，而不污染原始来源。

### 9.5 行内 AI

1. 用户停在句尾或选中文字；建议可关闭，连续输入和输入法组合阶段不打扰。
2. 系统根据当前块和相邻上下文给出续写、排版或内容建议；涉及取舍时提供选项及依据，不替用户做决定。
3. 用户用 `Tab` 接受、`Esc` 拒绝或打开 diff；不抢焦点、不自动改原文，拒绝后不立即重复建议。
4. 接受动作进入同一撤销栈并记录模型、上下文范围与时间。

### 9.6 安装 Skill

1. 用户导入本地 Skill 包或从可信来源获取。
2. 系统校验清单、签名、版本、权限和兼容性。
3. 用户逐项授权网络、文件、照片或写入能力。
4. Skill 在隔离运行时中执行；所有工具调用都有日志与撤销边界。
5. 用户可停用、回滚版本或完整卸载。

| FR-PRIV-03 | P0 | AI provenance：模型、版本、输入范围、来源、时间 | 每个派生块都可检查 |
| FR-PRIV-04 | P0 | 原始内容不可变和内容哈希 | 篡改可检测，删除需进入回收站/保留期 |
| FR-PRIV-05 | P1 | 每库远程 AI、联网、精确位置、健康等开关 | 关闭后后台作业也停止外发 |
| FR-PRIV-06 | P1 | 可选的库级加密与安全导出 | 恢复流程经过演练且不会锁死用户 |

## 11. AI 风险分级

| 级别 | 示例 | 默认策略 |
|---|---|---|
| L0 只读 | 搜索、问答、解释 | 可直接执行，记录来源 |
| L1 派生 | 摘要、标签候选、embedding、OCR | 可自动生成，可随时重建 |
| L2 可逆写入 | 新建知识页、添加链接、接受行内建议 | 可按规则自动，但必须进入事务和撤销链 |
| L3 结构变更 | 合并页面、迁移 schema、批量重命名 | 必须显示影响预览并由用户确认 |
| L4 外部影响 | 网络工具、日历写入、文件导出到库外 | 每类能力单独授权；敏感操作逐次确认 |

删除原始来源、清空历史、覆盖冲突版本不允许由 AI 自主执行。用户原文的内容或排版修改必须先接受建议；L2 自动应用仅面向规则允许的派生内容。个人画像复用知识页和既有审阅入口；仅使用授权记录，不由一篇日记推断稳定人格或敏感属性，停用后停止更新及用于个性化。

## 12. 数据与内容生命周期

1. **Capture**：先落本地操作日志和原始内容，返回可编辑状态。
2. **Normalize**：解析块、媒体与来源，生成内容哈希；原文全文索引后置于保存独立更新，不等待模型。
3. **Enrich**：提取实体、摘要、候选主题与向量；均为派生数据。
4. **Propose**：形成可解释的知识库修改方案。
5. **Apply**：按风险与规则自动或人工应用为原子事务。
6. **Index**：按已提交变更更新派生内容的全文、向量、关系和时间索引。
7. **Sync**：上传变更与附件，处理合并。
8. **Review**：lint、周期回顾和低置信度任务进入收件箱。
9. **Archive/Delete**：先回收站，再按用户保留期清理；备份策略明确提示。

## 13. 边界与异常场景

- 模型不可用、限流、密钥失效：写作与本地检索继续，作业排队并显示原因。
- AI 返回无效结构：拒绝写入，保留原始响应摘要供诊断。
- 导入同一来源：依据内容哈希幂等；保留新的访问时间和来源上下文。
- 多设备同时改同一块：可自动合并不相交修改；重叠修改生成冲突副本。
- 外部文件被移动或权限撤销：保留缩略信息，提供重新授权，不反复弹窗。
- Photos/Music/Location/Weather/Health 权限拒绝：对应模块消失，手帐仍完整可用。
- 大附件或磁盘不足：导入前估算，失败不留下半成品引用。
- 知识规则改变：先生成迁移预览，旧结构在迁移完成前仍可查询。
- Skill 崩溃或超时：隔离终止，不拖垮主编辑器，未提交事务全部回滚。

## 14. 可访问性与国际化

- VoiceOver 能描述导航层级、块类型、媒体、AI 状态与变更 diff。
- Full Keyboard Access 覆盖全部交互，焦点顺序与视觉顺序一致。
- 支持减少动态效果、增加对比度和系统辅助设置。
- 简体中文和英文为首批语言；日期、时间、温度和单位遵循区域设置。
- AI 输出语言默认跟随当前记录，不由界面语言强制覆盖。

## 15. 依赖与约束

- macOS 的 HealthKit 本地数据源不可被当作 iPhone 等价物，健康能力需要 iPhone 伴侣桥接。
- Apple Foundation Models 的设备、地区和模型状态可能不可用，必须通过统一路由降级到本地或 BYOK 模型。
- iCloud 同步是异步且时机不确定，所有功能必须以本地提交成功为用户完成条件。
- 第三方模型 API、MCP 与 Skills 都是可插拔依赖，不得成为打开或编辑内容的前置条件。
- 知识图谱 UI 依赖独立设计验收，底层数据接口完成不等于界面可以上线。
