# Synora Wiki 验收标准

状态：NOT_RUN。需求与数值是目标，不是实现证据；历史 Web QA 不作为原生验收。

## 产品验收场景

完整版本必须端到端通过以下场景：

1. 离线冷启动，新建 5,000 字手帐，插入 30 张图和 2 个视频，退出并恢复，内容与布局一致。
2. 导入 1,000 个异构文件，强制中断三次，恢复后无重复、无丢失，全部来源可追溯。
3. 配置两个 BYOK 供应商与一个本地模型，分别路由轻任务、深度问答和行内建议；任一供应商失败可无损切换。
4. AI 对 100 条记录提出重组方案，用户查看 diff、接受一半、拒绝一半，再撤销已接受部分，索引与页面一致。
5. 安装一个只读 Skill 与一个请求写入/联网的 Skill，验证权限隔离、日志、停用、降级和卸载。
6. 两台设备同时编辑同一记录，验证不相交块自动合并、相交块进入冲突审阅且不静默丢失。
7. 从完整备份在空白环境恢复，全文、附件、链接、规则、作业历史和 AI provenance 均可用。
8. 仅用键盘和 VoiceOver 完成新建、写作、插图、搜索、AI 建议、版本恢复。

## 技术验收标准

1. 全部 FR 有可追踪测试或人工设计验收项，无“按钮存在即完成”。
2. 从 v1 空库到 10k 记录数据集，迁移、重建索引、备份和恢复均可重复。
3. 任一 AI provider、CloudKit、Skill runtime 或 Apple 集成故障不阻止离线编辑。
4. 人工故障注入后 operation log、SQLite projection、开放导出三者哈希一致。
5. 对同一操作序列重复 ingest/sync 不产生重复页面、块、关系或附件。
6. 所有 AI 写入都有 ChangeSet、provenance 与可执行反向操作。
7. 全部密钥和敏感正文通过日志扫描；构建产物不含测试凭据。
8. 高保真截图、键盘流程、VoiceOver 流程通过 `DESIGN.md` 和 `PRODUCT.md` 验收。
9. 知识图谱只在独立设计评审通过后启用；未通过时保持后端 API，不发布粗糙 UI。

## 阶段退出门槛

### P0 — 架构与风险探针

- P0-04/06/07 探针覆盖的硬性场景无未知致命阻塞；主方案失败时备选必须实际跑通。
- 主线程输入预算、CloudKit 收敛和 XPC 隔离均有可重复测量结果。
- 架构审查确认 UI、领域、基础设施依赖方向无反转。
- 全部 ADR 含选择、备选、证据、后果、回滚点；干净环境 build/unit/lint 实测。

### P1 — 原生壳层与设计系统

- 关键壳层 SSIM ≥ 0.95，尺寸/颜色误差符合 `DESIGN.md`。
- 仅键盘完成栏位切换、列表选择、检查器切换和命令调用。
- 所有状态无裁切、横向滚动或焦点丢失。
- 三尺寸无拉伸、遮挡或错误空白；全部主路径键盘可达。

### P2 — 完整编辑与多媒体

- 100k 字+200 媒体记录可编辑，keystroke-to-paint P95 ≤ 16 ms。
- 强制终止后恢复已确认输入；没有孤立附件。
- 所有 block 类型完成往返与撤销测试。
- VoiceOver 能读出块类型、媒体说明和编辑状态。
- 块结构与 ID、未知属性往返保留，首屏满足 TESTING 预算；本阶段已有真实编辑持久化。

### P3 — 本地数据、检索与开放库

- 10k 记录 FTS P95 ≤ 150 ms。
- 1,000 文件重复导入和中断恢复后零重复、零悬空、零不可追溯内容。
- 空白环境可仅从导出/备份恢复完整库。
- 随机 operation 序列重放保持不变量和最终哈希一致。
- 备份恢复记录、附件、历史及非密钥设置；开放导出与运行态核对。

### P4 — AI Runtime、BYOK 与行内 AI

- 替换供应商不改领域层；任一供应商故障不阻止编辑/检索。
- 无效 JSON、越权工具、超预算、超时均不能产生半提交修改。
- 100% AI 写操作有 ChangeSet、引用、模型版本和可执行撤销。
- 行内 AI 取消 ≤ 100 ms，且任何网络状态下不阻塞输入。
- 本地/系统、OpenAI-compatible、OpenAI/Anthropic/Gemini adapter 契约检查及真实能力证据分别记录；运行真实提案/提交/撤销链。无模型不得标通过。

### P5 — LLM Wiki 引擎

- Raw/User 层从模型后台路径不可写，编译边界和运行时双重验证；派生内容可全量重建。
- 每个知识事实都有有效 citation 或明确的“用户手工结论”标记。
- 重复 ingest 幂等；中断后恢复不重复写入。
- schema 迁移可预览、可取消、可回滚。
- 确定性部分可重复；模型质量阈值在阶段执行计划中预先确定并用真实 runtime 验收，不在测试后放宽。

### P6 — Skills 与 MCP

- 未授权 Skill 访问文件/网络/写入成功率为 0，未授权外发为 0。
- 崩溃 Skill 不影响主应用，未提交写入全部回滚。
- 任意版本可停用、降级、卸载；审计日志完整，隔离崩溃不得拖垮主应用。
- 失败安装回到上一稳定版本，权限、版本、任务和影响对象可追踪。

### P7 — Apple 生态与多设备同步

- 72 小时断网、多设备并发、账户切换和重复推送测试最终收敛。
- 同一块重叠编辑不静默覆盖；冲突双方可读、可选择、可合并。
- 拒绝任一 Apple 权限不影响核心记录体验。
- Mac 端只接收用户选择的健康摘要，不复制 HealthKit 原始 sample。
- 新设备按需恢复文字与选定媒体，授权拒绝无循环弹窗。

### P8 — 回顾、知识体验与图谱设计门

- 用户无需维护目录即可完成记录—整理—查询—回顾闭环。
- 回顾/建议可关闭、可调频，不造成持续提醒压力。
- 图谱若启用：节点清晰、缩放稳定、选择可追踪、力导向动画优雅，10k 节点交互保持目标帧率；否则不以粗糙版本替代。
- 图谱未通过独立门槛时明确等待设计，不以粗糙 UI 冒充完成。

### P9 — 系统级验证与个人发布

- 本文件八个端到端验收场景全部通过。
- 本文件技术门槛、TESTING.md 性能预算及 DESIGN.md 视觉门槛全部通过。
- 发布构建可在干净机器安装、创建、导入、同步、备份和恢复。
- 没有 P0/P1 数据丢失、安全、崩溃、可访问性或核心视觉缺陷。
- 全部 P0/P1/P2 需求完成；无测试证据不算交付，发布构建在干净设备复验。

## 跨阶段质量门

每个阶段结束都必须更新：

- FR → SPEC → PLAN → 测试用例的 traceability matrix。
- 数据 schema 与迁移版本；fixture 至少覆盖前一发布版本。
- 视觉 snapshot、键盘路径、VoiceOver 路径。
- 性能趋势图和预算回归。
- threat model、新增权限和隐私说明。
- ADR、已知限制和下一阶段风险。

任何指标退化都需要明确的 owner、原因、修复阶段和临时保护；不得用“后续优化”绕过数据正确性、安全或可撤销性。

## 判定

执行者提交证据，测试与评审独立判定 PASS / CHANGES_REQUIRED / BLOCKED。日志必须标明 HEAD、环境、命令、退出码、产物位置与未验证项。只有所有适用门槛通过才关闭阶段；不确定条件保持未决，不自行豁免。
