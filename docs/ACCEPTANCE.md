# Synora Wiki 验收标准

适用范围以 [PRODUCT §5.3](PRODUCT.md#53-当前服务与交付边界) 为准；DEFERRED 项不进入任何已规划阶段的依赖、完成率或退出门槛，不记为 BLOCKED，不要求 Apple 开发者账号。

本文保留阶段出口和完整版本目标；实时状态只记入 PLAN 和 traceability。需求与数值是目标，不是实现证据。

## 完整版本验收场景

以下场景在 P9/发布候选时统一端到端验收，不作为前置阶段或普通提交的重复门槛：

1. 离线冷启动，无需选择目录/标签即可新建 5,000 字手帐，插入 30 张图和 2 个视频，退出并恢复，内容与布局一致。
2. 导入 1,000 个异构文件，强制中断三次，恢复后无重复、无丢失，全部来源可追溯。
3. 配置两个 BYOK 供应商与一个本地模型，分别路由轻任务、深度问答和行内建议；任一供应商失败可无损切换。
4. AI 对 100 条记录提出重组方案，用户查看 diff、接受一半、拒绝一半，再撤销已接受部分，索引与页面一致。
5. 安装一个只读 Skill 与一个请求写入/联网的 Skill，验证权限隔离、日志、停用、降级和卸载。
6. 在手帐中通过搜索及粘贴 Apple Music 链接创建音乐卡片，点击交接外部音乐应用；通过 CoreLocation + Open-Meteo 保存天气快照。断网重开与备份恢复后元数据保留，失败不阻塞写作。原双设备场景 DEFERRED。
7. 从完整备份在空白环境恢复，全文、附件、链接、规则、作业历史和 AI provenance 均可用。
8. 仅用键盘和 VoiceOver 完成新建、写作、插图、搜索、AI 建议、版本恢复。

## 完整版本技术标准

1. 全部在范围内 FR 有可追踪测试或人工设计验收项，无“按钮存在即完成”。
2. 从 v1 空库到 10k 记录数据集，迁移、重建索引、备份和恢复均可重复。
3. 任一 AI provider、公开音乐天气 API、Skill runtime 或 Apple 集成故障不阻止离线编辑。
4. 人工故障注入后 operation log、SQLite projection、开放导出三者哈希一致。
5. 对同一操作序列重复 ingest/导入/作业重试 不产生重复页面、块、关系或附件。
6. 所有 AI 写入都有 ChangeSet、provenance 与可执行反向操作。
7. 全部密钥和敏感正文通过日志扫描；构建产物不含测试凭据。
8. 高保真截图、键盘流程、VoiceOver 流程通过 `DESIGN.md` 和 `PRODUCT.md` 验收。
9. 知识图谱只在独立设计评审通过后启用；未通过时保持后端 API，不发布粗糙 UI。

## 阶段退出门槛

### P0 — 架构与风险探针

- 工程骨架可构建，相关单测/格式检查有一次当前代码证据。
- TextKit 2、GRDB/WAL/replay 和 XPC/WASI 各用最小代表性场景回答可行性问题；失败时记录原因、影响和备选，不强制在 P0 做完备选产品。
- 基准生成器的 smoke profile 可确定性重现，full profile 规模定义明确；20 GiB 物理生成和完整媒体验证由 P3/P9 承担。
- 适用 ADR 记录当前选择、证据、未决风险和回退点。P0-06 与同步 ADR 为 DEFERRED，不是 blocker。
- 真实输入法/VoiceOver/长文性能、完整存储故障矩阵、完整 broker/恶意 Skill 矩阵和发布级检查分别属于 P2、P3、P6 和 P9，不阻塞 P0。

### P1 — 原生壳层与设计系统

- 关键壳层 SSIM ≥ 0.95，尺寸/颜色误差符合 `DESIGN.md`。
- 仅键盘完成栏位切换、列表选择、检查器切换和命令调用。
- 所有状态无裁切、横向滚动或焦点丢失。
- 三尺寸无拉伸、遮挡或错误空白；全部主路径键盘可达。

### P2 — 完整编辑与多媒体

- 100k 字+200 媒体记录可编辑，keystroke-to-paint P95 ≤ 16 ms。
- 强制终止后恢复已确认输入；没有孤立附件。
- 所有 block 类型完成往返与撤销测试。
- VoiceOver 能读出块类型、媒体说明和编辑状态。
- 块结构与 ID、未知属性往返保留，首屏满足 TESTING 预算；本阶段已有真实编辑持久化。

### P3 — 本地数据、检索与开放库

- 10k 记录 FTS P95 ≤ 150 ms。
- 1,000 文件重复导入和中断恢复后零重复、零悬空、零不可追溯内容。
- 空白环境可仅从导出/备份恢复完整库。
- 随机 operation 序列重放保持不变量和最终哈希一致。
- 备份恢复记录、附件、历史及非密钥设置；开放导出与运行态核对。

### P4 — AI Runtime、BYOK 与行内 AI

- 替换供应商不改领域层；任一供应商故障不阻止编辑/检索。
- 无效 JSON、越权工具、超预算、超时均不能产生半提交修改。
- 100% AI 写操作有 ChangeSet、引用、模型版本和可执行撤销。
- 行内 AI 取消 ≤ 100 ms，且任何网络状态下不阻塞输入；原文/排版修改经接受才提交，拒绝不重复打扰，过期建议不应用。
- 总上下文与调用费用预算可观测、可限制；节省调用的策略通过质量回归，不能仅凭缓存命中宣称成本达标。
- 本地/系统、OpenAI-compatible、OpenAI/Anthropic/Gemini adapter 契约检查及真实能力证据分别记录；运行真实提案/提交/撤销链。无模型不得标通过。

### P5 — LLM Wiki 引擎

- Raw/User 层从模型后台路径不可写，编译边界和运行时双重验证；派生内容可全量重建。
- 每个知识事实都有有效 citation 或明确的“用户手工结论”标记。
- 重复 ingest 幂等；中断/并发/取消后不重复写入或覆盖新 revision；产物缺失可修复，tombstone 不复活。
- index/log 可确定性重建；原文可独立检索，双通路回答在预算内引用有效证据；解析不完整不冒充完整导入。
- 来源删除保留其他来源、人工修改与历史；结构 lint 无模型可用，语义问题仅按风险提案处理。
- schema 迁移可预览、可取消、可回滚。
- 确定性部分可重复；模型质量阈值在阶段执行计划中预先确定并用真实 runtime 验收，不在测试后放宽。

### P6 — Skills 与 MCP

- 未授权 Skill 访问文件/网络/写入成功率为 0，未授权外发为 0。
- 崩溃 Skill 不影响主应用，未提交写入全部回滚。
- 任意版本可停用、降级、卸载；审计日志完整，隔离崩溃不得拖垮主应用。
- 失败安装回到上一稳定版本，权限、版本、任务和影响对象可追踪。

### P7 — macOS 本地上下文与公开服务

- 自有 Music Picker 搜索和分享链接两入口创建原生 MusicBlock，保存元数据及 URL，离线可读、可撤销、可导出恢复；不复制音频，不要求 Apple Music 订阅来创建卡片。
- Apple Music 链接在真实 Mac 验证交接 Music；系统不能交接时有可用外部网页/复制回退。无结果/缺封面仍为音乐卡片，可手工补全，不误配歌曲。
- CoreLocation + Open-Meteo 展示并保存温度、天气码/描述、降水、日出日落（允许合理缺值）和来源/时间/时区；不请求 WeatherKit。
- 定位/联网拒绝、取消、服务故障不影响记录；坐标外发说明与精度控制有效，旧快照不被覆盖，来源标注可见。
- 免费可用的照片、地图、系统入口及卡片通过真实集成、权限、三尺寸和可访问性验证；不用 mock 替代产品验收。
- 无 Apple 付费会员、CloudKit/iCloud、MusicKit entitlement 或 Developer Token 前置依赖；同步和 iPhone 相关项为 DEFERRED，不计入本阶段出口。

### P8 — 回顾、知识体验与图谱设计门

- 用户无需维护目录即可完成记录—整理—查询—回顾闭环。
- 回顾/建议可关闭、可调频，不造成持续提醒压力。
- 个人画像区分事实与推测、可追溯和纠正；停用/删除、来源撤回及本地备份恢复后不继续使用失效信息，不把单次行为固化为人格判断。
- 图谱若启用：节点清晰、缩放稳定、选择可追踪、力导向动画优雅，10k 节点交互保持目标帧率；否则不以粗糙版本替代。
- 图谱未通过独立门槛时明确等待设计，不以粗糙 UI 冒充完成。

### P9 — 系统级验证与个人发布

- 本文件八个端到端验收场景全部通过。
- 本文件技术门槛、TESTING.md 性能预算及 DESIGN.md 视觉门槛全部通过。
- 发布构建可在干净机器本地运行、创建、导入、备份和恢复。
- 没有 P0/P1 数据丢失、安全、崩溃、可访问性或核心视觉缺陷。
- 全部在范围内 P0/P1/P2 优先级需求完成；无测试证据不算交付，发布构建在干净设备复验。

## 阶段收口原则

- 每个阶段只验证该阶段明确交付的行为和直接依赖。
- 只有实际发生变化时才更新对应 traceability、schema/迁移、视觉/可访问性、性能、权限/安全或 ADR 记录。
- 数据正确性、权限、安全和不可撤销写入仍必须失败关闭；其他未属于当前阶段的生产化验证移交到对应阶段，不视为豁免功能。

## 判定

普通改动由执行者运行相关检查。阶段依据本阶段门槛判定 PASS / CHANGES_REQUIRED / BLOCKED。完整版本/发布候选或用户明确要求时，再由独立测试和独立评审做对抗性判定。任何未运行项都必须如实说明。
